# VulnAgent Roadmap

- 文档版本：2026-11-03
- 当前里程碑：`v0.7.8`（开发版标识 `0.7.8-dev`）
- 维护方式：每个版本发布前更新本文件与 [CHANGELOG.md](CHANGELOG.md)；版本计划会随实际反馈调整，不代表交付承诺。

## 1. 产品定位与当前基线

VulnAgent 是面向主机与软件组件的**漏洞运营控制面**：Agent 采集 SBOM 与运行遥测，控制面完成 CVE / EPSS / KEV / OSV 匹配、可解释风险排序、工单闭环与复扫验证；在此之上提供受控的 Agent 助手与 SSH 运维能力。

截至 `v0.7.8` 已具备：

| 领域 | 已落地能力 |
|---|---|
| 采集 | 单机 Agent（独立身份/心跳/命令）、全局令牌兼容、SSH 只读兜底、网段发现 |
| 漏洞 | CVE/EPSS/KEV/OSV、产品映射、风险加权、P0–P3、工单与复扫验证 |
| 资产 | CMDB 档案、CSV 导入导出、合并、关系拓扑、业务系统权重、云/CMDB 只读同步、资产直连终端与 SSH 凭据复用 |
| 运维 | SSH 终端、SFTP、会话录制/协同、命令参考、主机性能监控、GPU/服务加速（含实时运行态与进程）、hashcat 审计、集群节点直连终端与内联 SSH 凭据 |
| 多主机 | 项目 → 集群 → 节点、异步检查/扫描、MySQL/PostgreSQL 只读深检、跨页漏洞/资产筛选、SLO/错误预算、依赖拓扑与根因候选 |
| 平台 | 网页运行配置、分级权限、审计与操作轨迹、自检、备份、Windows/Linux 部署脚本 |

## 2. 版本策略

- 采用语义化版本 `MAJOR.MINOR.PATCH`：不兼容变更升 MAJOR，功能里程碑升 MINOR，修复升 PATCH。
- 每个版本必须包含：更新日志、迁移说明、验收结果、回滚方式。
- 数据库迁移在一个 MINOR 内保持向后兼容；删除字段/表只允许在 MAJOR 版本。
- 正式发布通过 `-ldflags "-X main.appVersion=… -X main.buildCommit=… -X main.buildTime=…"` 注入版本与构建信息，并打 Git tag。
- 当前仓库尚未打 tag，`CHANGELOG.md` 中的历史版本为按提交区间回溯的里程碑，终点提交即当时的 `origin/master` 推送。

## 4. v0.8.0 · 生产可用性

目标：从「功能可用」提升到「可长期值守」，减少人工巡检与静默失败。

| 优先级 | 事项 | 说明 | 验收标准 |
|---|---|---|---|
| P0 | 告警中心 | 规则（P0 新增、Agent 离线、检查失败、同步失败、磁盘/连接数阈值）、静默窗口、飞书/Webhook/邮件通道 | 规则可启停；触发去重；告警与恢复成对出现；写审计 |
| P0 | 集群定时巡检 | 按 Cron 对集群执行检查/扫描；失败自动重试；保留最近 30 天结果 | 可视化任务历史；连续失败告警；可手动触发 |
| P0 | Agent 生命周期 | 版本上报与漂移视图、批量注册、吊销审计、升级包分发 | 可看到版本分布；可批量生成令牌；升级失败可回滚 |
| P0 | 权限细化 | 项目成员与集群级只读/运维角色；API Token（只读/自动化） | 非成员看不到项目；Token 可单独吊销；越权测试通过 |
| P1 | 数据库深检扩展 | Redis、MongoDB、Elasticsearch；复制延迟、慢查询开关、连接池水位 | 至少 3 种引擎；只读账号最小权限说明；凭据加密 |
| P1 | 可观测性 | Prometheus 指标补齐（任务、Agent、集群）、结构化日志、慢请求追踪 | 关键路径有指标；日志可检索；有 Grafana 示例面板 |
| P1 | 备份与恢复演练 | 自动备份、完整性校验、恢复向导与演练记录 | 备份失败告警；恢复步骤可执行；演练留痕 |
| P2 | 报表增强 | 集群/项目维度周报、SLA 统计、趋势导出 | 可按项目生成 PDF/CSV；口径与列表一致 |

## 5. v0.9.0 · 分布式与规模化

目标：支持更大资产规模、跨网络与多控制面场景。

| 优先级 | 事项 | 说明 | 验收标准 |
|---|---|---|---|
| P0 | PostgreSQL 存储 | 抽象仓储适配 Postgres，提供 SQLite → Postgres 迁移工具 | 迁移可回滚；核心查询性能不下降；双库测试通过 |
| P0 | 任务队列 | 检查/扫描/同步任务持久化队列，支持重试、死信与并发配额 | 重启不丢任务；可限制每集群并发；失败可重放 |
| P0 | Agent Relay | 内网 Agent 通过 Relay 反向连接控制面，支持多级转发 | Relay 断线重连；身份透传；不降低签名校验 |
| P1 | 多控制面只读聚合 | 区域控制面向上汇总资产/漏洞/集群状态，不双向写 | 汇总延迟可配置；冲突只读展示；可关闭 |
| P1 | 对象存储备份 | S3/OSS 备份与保留策略 | 生命周期可配置；恢复校验通过 |
| P1 | 规模目标 | 单控制面 5,000 资产 / 50 万组件 / 10 万漏洞 | 列表 P95 < 800ms；扫描吞吐可线性扩展 |
| P2 | 审计导出 | 审计与操作轨迹批量导出、外部 SIEM Webhook | 支持时间范围与过滤；失败重试 |

## 7. 探索方向（不承诺）

- **AI 修复闭环**：从修复建议到变更计划、审批、执行、复扫验证的完整链路。
- **运行时资产**：基于 eBPF 的进程/端口/容器运行时清单，与 SBOM 交叉验证。
- **Kubernetes Operator**：以 CRD 管理扫描任务、Agent 与策略。
- **SBOM 可信**：Sigstore 签名、attestation、供应链来源校验。
- **CMDB 双向同步**：带审批的写回，处理冲突与回滚。
- **私有情报与研判**：企业私有的漏洞/资产情报源，LLM 辅助降噪与归因。

## 8. 非目标

- 不做攻击性扫描、漏洞利用或口令爆破（hashcat 仅用于授权口令审计）。
- 不替代 SIEM/日志平台，不做全量日志采集与关联分析。
- 不替代企业 CMDB，默认只读同步。
- 不在无审批情况下自动变更生产主机。
- 不做多租户 SaaS 计费体系（企业内网部署优先）。

## 9. 优先级原则

1. **安全边界优先**：任何自动化都必须可审计、可回滚、最小权限。
2. **先可观测再扩展**：没有指标、告警与验收数据的能力不进入默认启用。
3. **兼容旧部署**：升级不破坏既有 Agent、脚本与数据；重大变更必须提供迁移工具。
4. **真实数据验证**：性能与稳定性结论来自真实规模数据，不使用演示数据作为验收依据。
